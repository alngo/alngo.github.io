Notes on "A Philosophy of Software Design" by John Ousterhout

Chapter 17 – Consistency

You’re navigating a new area of a large codebase…
Suddenly, it feels familiar.
Something clicks in your brain—it’s satisfying.
What you’ve seen before helps you understand what you’re seeing now.
Your brain connect this snippet to a wider mental map you’ve been building over time.

As John Ousterhout wrotes:
“Consistency creates cognitive leverage: once you’ve learned how something is done in one place, you can use that knowledge to immediately understand other places that use the same approach.”

When reading a codebase, some patterns are immediately accessible:
- Naming conventions
- Code formatting
- Folder and file structure

Others require deeper exposure and learning:
- Design patterns
- Architecture 
- Business Domain

So how do we "learn how something is done in one place"?
I believe it starts with reading code, 
not only what you are working on but also open source projects and unfamiliar systems.
The more code you read, the more patterns you’ll recognize.
You just need to read enough code to see it.

Expose yourself to more code. Your brain will do the rest.
That’s how you build intuition. That’s how you level up.
